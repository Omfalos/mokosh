# Issue 5 — `find_duplicates` and `cycles` produce noise that isn't actionable

Status: proposed, not started. Found dogfooding v0.5.0 against mokosh itself and JVM
monorepos (2026-09-03).

## Symptom

Both outputs bury real findings under false positives, so users learn to ignore them.

### 5a — `cycles` reports documentation cross-links as circular dependencies

`analyze` on the mokosh repo itself (`src/index.ts`, `src/cli.ts`, `src/mcp.ts` as entry
points) returns **four cycles, all of them markdown docs referencing each other**, zero code
cycles:

```
docs/adr-011-go-python-call-edges.md ↔ docs/adr-003-call-edge-graph.md
docs/monorepo.md → docs/adr-017-jvm-languages.md → docs/jvm-support-followups.md → docs/architecture.md → docs/monorepo.md
README.md → docs/mcp.md → docs/monorepo.md → … → README.md
docs/architecture.md ↔ docs/query.md
```

Markdown code-span file references (ADR-009) are added as real graph edges, and
`GraphAnalyzer.findCycles` (`src/graph/analyzer.ts`, `GraphAnalyzer.findCycles`) treats them
like imports. Docs linking each other is normal and not a defect — reporting it as a "circular
dependency" is pure noise. The JVM same-package clique
(issue 3, fixed in #11) is the other big contributor.

### 5b — `find_duplicates` reports non-actionable repetition

Recurring false-positive classes observed:

- Generated / vendored code (protobuf output, `*.generated.*`, OpenAPI clients).
- Boilerplate that *should* look alike: DTO/POJO getters/setters, `equals`/`hashCode`,
  Redux-style action creators, test `beforeEach` scaffolding, barrel re-export lists.
- License / copyright headers repeated verbatim across every file.
- Import blocks — long shared import lists tokenize identically.
- Structurally identical but semantically unrelated blocks that survive the
  `maxPunctuationRatio` gate.

The engine already has noise mitigations (`maxPunctuationRatio`, family partitioning, lock
file exclusion — `src/graph/duplication/index.ts`), but they don't cover the above.

## Root cause

- `findCycles` has no notion of edge *kind* — markdown-reference edges, JVM synthetic
  same-package edges, and real `import`s are all walked identically
  (`src/graph/analyzer.ts`, the `imp.isExternal` / empty-`toPath` skip is the only filter).
- `find_duplicates` operates on a normalized token stream with no signal for "this file is
  generated", "this span is an import block / header comment", or "this is a
  language-idiomatic accessor". `tokenize()` (`src/graph/duplication/tokenizer.ts`) strips
  comments but keeps import statements; nothing tags generated files.

## Fix plan

### 5a — kind-aware cycle detection

- Introduce an edge-kind concept (reuse `ImportEdge.type` + the new `isSamePackage` flag from
  issue 3 (fixed, #11); add `isDocReference` for markdown code-span
  edges, set where ADR-009 references are resolved).
- `findCycles` skips `isSamePackage` and `isDocReference` edges by default. Add an opt-in
  `includeKinds` param to `analyze` / a dedicated `find_cycles` tool for callers who do want
  doc-link loops.
- Report cycles with the edge kinds involved so a caller can see *why* something is a cycle.
- Consider excluding `category: "test"` → source back-edges (a test importing its subject is
  not a cycle worth flagging) behind a flag.

### 5b — generated-code and structural filtering for `find_duplicates`

- **Generated-file detection**: skip files matching common generated markers — path globs
  (`**/generated/**`, `**/__generated__/**`, `*.pb.go`, `*_pb2.py`, `*.g.dart`,
  `*.generated.ts`) and a first-line/first-500-bytes scan for `@generated`,
  `DO NOT EDIT`, `Code generated by`. Expose as `find_duplicates({ includeGenerated: false })`
  (default false) plus `MokoshConfig.duplication.ignoreGlobs`.
- **Strip import/using/require blocks** before tokenizing (per-language, in `tokenize()`),
  same rationale as comment stripping — shared imports are not shared logic.
- **Strip leading license/header comment blocks** explicitly (already dropped as comments,
  but verify block-comment headers before the first token are gone).
- **Accessor / boilerplate suppression** (language-aware, ties into
  [issue 7](07-per-language-analysis-semantics.md)): down-rank or drop blocks that are
  entirely trivial getters/setters, `equals`/`hashCode`/`toString`, enum bodies.
- **Minimum distinct-identifier threshold**: require a duplicate block to contain at least N
  distinct non-keyword identifiers, so a run of pure structural punctuation + one repeated
  name doesn't qualify (complements `maxPunctuationRatio`).
- **Report confidence / reason**: annotate each `DuplicateGroup` with a `signals` list
  (`"same-file"`, `"crosses-package"`, `"mostly-accessors"`, `"contains-imports"`) so callers
  and [issue 6](06-duplicates-query-language.md)'s query layer can filter.

## Expected outcome

- `analyze` `cycles` on mokosh returns `[]` (correct — there are no code cycles), and on JVM
  repos returns only genuine import cycles.
- `find_duplicates` default output on a repo with generated code and DTOs shrinks to
  human-actionable findings.

## Test plan

- Unit (`src/graph/analyzer` test): a graph with only markdown-reference edges in a loop →
  zero cycles by default, N cycles with `includeKinds: ["docReference"]`.
- Unit: real `a.ts → b.ts → a.ts` import cycle still reported.
- Unit (`src/graph/duplication/index.test.ts`): a `@generated`-headed file with an obvious
  duplicate is excluded by default, included with `includeGenerated: true`.
- Unit: two files sharing only a 20-line import block report **no** duplicate.
- Unit: `DuplicateGroup.signals` populated correctly for a same-file vs cross-package match.
- Regression: existing duplication fixtures still detected.
